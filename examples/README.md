# Подключение своего сайта

`demo.html` и `demo.js` показывают работу через протокол NCALayer без внешних
библиотек. На HTTPS-доменах `.kz` адаптер включён сразу; на другом HTTPS-домене
нужно разрешить доступ через значок расширения и обновить страницу.

Для локальной разработки можно разместить эти файлы на обычном HTTP-сервере
localhost/127.0.0.1. Такой сервер нужен только для тестового сайта, само
расширение в нём не нуждается. Страница запрашивает `basics.sign` с явными
параметрами без TSA; пользователь подтверждает операцию в окне расширения.

Basics по умолчанию требует цепочку НУЦ. Для одноразового самоподписанного
тестового сертификата можно явно задать `signerParams.chain: []`; интерфейс
покажет, что доверие к УЦ не подтверждено. Для своего УЦ передайте PEM-якоря
в `signerParams.chain`. Для CMS с меткой НУЦ добавьте `tsaProfile: {}` в
`signingParams`. Для готового хеша: `decode: true, digested: true,
encapsulate: false`; данные — Base64 хеша алгоритма выбранного сертификата.

В рабочей системе результат следует независимо проверять на сервере,
включая цепочку доверия, срок, отзыв, назначение сертификата и связь подписи
с одноразовым запросом/конкретным документом. Пример демонстрирует клиентскую
интеграцию и не реализует серверную аутентификацию.
