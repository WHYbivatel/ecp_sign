# Tegin

Браузерное расширение для локального подписания ключами ЭЦП НУЦ РК.
**Конечному пользователю не нужны NCALayer, Java, native host или локальный сервер.**

**Скачать:** Chrome / Edge 0.5.3 — на [tegin.esl.kz](https://tegin.esl.kz/) (сборка `dd40b5e`);
Firefox 0.5.2 — [GitHub Releases](https://github.com/WHYbivatel/ecp_sign/releases/download/v0.5.2/tegin-firefox-0.5.2.zip) ·
[Инструкция установки](INSTALL.md)

Архив нужно распаковать, затем в `chrome://extensions` включить режим
разработчика и выбрать распакованную папку через «Загрузить распакованное».
Папку после установки не удаляйте.

Этот README описывает код ветки `codex/nca-key-issuance` (версия в манифесте 0.5.3); он новее
опубликованных архивов. Tegin открывает защищённые PKCS#12, подписывает, показывает
подтверждение и возвращает результат сайту. Полная совместимость со всеми порталами и всеми
модулями NCALayer не подтверждена: что проверено и где — в [матрице поддержки](docs/support-matrix.md).

## Установка Chrome / Edge / Chromium

Готовая сборка доступна по ссылке выше. При сборке из исходников — `dist/chromium`.

1. Открыть `chrome://extensions` (в Edge — `edge://extensions`).
2. Включить режим разработчика → «Загрузить распакованное расширение».
3. Выбрать папку `dist/chromium`.
4. Обновить страницу портала, выбрать вход/подписание по ЭЦП.
5. В окне расширения проверить адрес и документ, выбрать `.p12` / `.pfx`,
   ввести пароль и подтвердить операцию.

На HTTPS-доменах `.kz` адаптер включается автоматически. На своём сайте с
другим доменом нажать значок расширения → «Подключить сайт» →
обновить страницу. Для разработки адаптер также работает на HTTP localhost
и 127.0.0.1. Подключение собственного сайта описано в `examples/`.

Нажатие значка Tegin сразу открывает обычную вкладку Chrome. «Подписать»,
«Проверить» и «На главную» работают в одной вкладке; можно пользоваться
кнопкой браузера «Назад». Повторное нажатие значка возвращает в уже открытый
Tegin. Подтверждение запроса от сайта остаётся отдельным защищённым окном.

Через «Подписать файл» выберите документ и ключ. По умолчанию создаётся CMS
с документом внутри; выбор специальных форматов, в том числе подписи внутри PDF
(PAdES-B-B, только ключи RSA), находится в «Дополнительных настройках». После подписи
можно скачать результат или сразу нажать «Проверить эту подпись» без повторного выбора файлов.

Для проверки загрузите `.p7s`, `.p7m` или `.cms`. Tegin сам определит, находится
ли документ внутри. Если он вложен, исходник не запрашивается. Если подпись
отдельная, появится поле исходного документа. При выборе новой подписи старый
исходник очищается. Ключ и пароль для проверки не нужны. Определение типа
файла не означает успешную проверку: криптография проверяется отдельным шагом.

После публикации в магазине установка станет обычной установкой дополнения.
Публикация ещё не выполнена. Safari пока не поддерживается.

## Что реализовано

| Возможность | Статус |
|---|---|
| Защищённый PKCS#12, DER и BER из Kalkan/BouncyCastle | Реализовано, проверено на тестовых контейнерах |
| RSA/SHA-256 | Web Crypto; независимая проверка Node crypto / OpenSSL |
| ГОСТ 34.10-2015, 512 бит, параметры НУЦ A | Реализовано; независимые проверки Python и официальным Kalkan |
| ГОСТ 2004 и ГОСТ 2015/256 | CMS/CAdES проверены официальным Kalkan на одноразовых контейнерах |
| CMS с документом и отдельная CMS-подпись | Реализовано |
| CAdES-BES без метки времени | Проверено OpenSSL и официальным Kalkan |
| XMLDSig целого XML, exclusive C14N | RSA, ГОСТ-512 и ГОСТ-2004 проверены официальным Kalkan; ГОСТ-256 XML отклоняется |
| Подтверждение операции, сведения о сертификате | Новый интерфейс: просмотр, SHA-256, сертификат, доверие, явное согласие |
| CAdES-T / RFC3161 | Реальный сервис НУЦ; криптография токена и привязка к подписи проверены также Kalkan |
| PAdES-B-B (подпись внутри PDF) | Только RSA и только в «Подписать файл»; CMS по ByteRange проверяет OpenSSL, при наличии — EU DSS и pyHanko. Ограничения ниже |
| Подпись готового хеша | CMS/CAdES/raw, с проверкой длины хеша |
| Цепочка доверия | Локальная проверка по встроенным официальным сертификатам НУЦ |
| Отзыв сертификатов | OCSP и CRL НУЦ для подписанта, промежуточного УЦ и TSA; отозванный, неизвестный или непроверенный сертификат НУЦ блокирует операцию ([подробно](docs/certificate-revocation.md)). E2E в Chromium и Firefox 160 на синтетических ответах |
| Выпуск ключа НУЦ (`generateCsr`, `importCertificate`) | Ключ ГОСТ-2015-512 создаётся в браузере, сохраняется `.p12` формата Kalkan ([подробно](docs/nca-key-issuance.md)). Заявка подтверждена на портале владельцем, установка сертификата — нет |
| Адаптер WebSocket NCALayer для сайта | Сквозные тесты Chromium; выпуск ключа и отзыв — также Firefox |
| Отмена, закрытие окна, навигация, таймаут | Реализовано |
| Firefox 140+ | Отдельная сборка; E2E выпуска ключа и отзыва в Firefox 160 на трёх ОС. Подписанная сборка из AMO не проверялась |
| Конкретные государственные порталы | Сквозной вход с реальным сертификатом ещё не проверен |

Поддерживается часть `commonUtils`: `getActiveTokens`, `getKeyInfo`,
`changeLocale`, `signXml`, `signXmls`, `createCAdESFromBase64` (BES),
`createCAdESFromBase64Hash` (BES по хешу), `createCMSSignatureFromBase64`
(CAdES-T с меткой НУЦ). У `basics.sign` поддерживаются `xml`, `cms`, `raw`,
несколько документов, `decode`, `encapsulate` (по умолчанию true), `digested`,
стандартный `tsaProfile: {}` для CMS и ограничения EKU/ИИН/БИН/серийного номера.
При `digested: true` CMS обязательно `encapsulate: false`.

По умолчанию Basics требует доверенную цепочку НУЦ. `signerParams.chain: []`
явно отключает это требование, а массив PEM-сертификатов задаёт доверенные
сертификаты сайта. Такое доверие отдельно обозначается в интерфейсе.
Произвольные TSA-адреса/профили отклоняются. Если запрошенная метка недоступна
или не проходит проверку, подпись без неё не выдаётся.

**Не реализованы:** CAdES-LT/LTA, XPath и доподписание XML, вторая подпись PDF,
аппаратные токены и JKS. Неизвестные требования не упрощаются молча.

**Ограничения PAdES-B-B:**

- только ключи RSA; для ГОСТ подпись внутри PDF отключена, пока профиль с казахстанскими
  OID не проверен независимым валидатором;
- только первая подпись: PDF с подписью, сертификацией (`/Perms`), полем подписи или формой
  XFA, а также зашифрованный PDF отклоняются до открытия ключа;
- документ сохраняется заново целиком (`pdf-lib`), без инкрементального обновления: байты
  файла меняются, а повреждённый, но читаемый PDF подписывается в восстановленном виде;
- подпись невидимая, предпросмотра страниц нет, метки времени нет (уровень B-B);
- доступно только в окне «Подписать файл», сайтам через протокол NCALayer не предлагается.

**Прочие ограничения:** ГОСТ-256 XML отключён — в официальном Kalkan XMLDSig нет
соответствующего алгоритма. XML подписывается целиком, с exclusive C14N (NCALayer использует
inclusive C14N). Документы до 2 МБ, контейнеры до 4 МБ, проверка CMS до 8 МБ, сообщение сайта
до 3 МБ. Это совместимый транспорт и часть API, а не реализация всех модулей NCALayer.

## Вход на eGov и в кабинет НУЦ

Публичные страницы передают старый фильтр «Аутентификация клиента»
(OID `1.3.6.1.5.5.7.3.2`). При этом НУЦ выпускает единые ГОСТ-2015 ключи,
которые служат и для подписи, и для аутентификации, без обязательного отдельного
AUTH_RSA: [объявление НУЦ от 26.04.2024](https://pki.gov.kz/ru/2024/04/26/Технические-работы-34/).

Tegin учитывает эту политику для действующих сертификатов ГОСТ-2015 с
назначением emailProtection, разрешением цифровой подписи и признаком
физического/юридического лица НУЦ. Обязательна независимая проверка цепочки
до встроенных закреплённых корней НУЦ; сертификат или корень, переданный
сайтом, сам по себе такую возможность не даёт. Для ФЛ учитывается начало
выпуска единых ключей 26.11.2022, для ЮЛ — 28.04.2024. Остальные ограничения
сайта (роль, ИИН/БИН, серийный номер, его допустимая цепочка) сохраняются.
Имя файла значения не имеет. Для старых раздельных ключей требуется AUTH_RSA
с назначением clientAuth.

Версия 0.5.2 принимает параметры публичной страницы НУЦ: `tsaProfile: null`
означает отсутствие метки времени, список допустимых сертификатов может
содержать до 24 записей (страница НУЦ передаёт 12). Неподдерживаемые устаревшие
корни не мешают пути через поддерживаемый допустимый корень; построение пути
только через неподдерживаемый корень не даёт доверия. Клиенты, отправляющие
запрос сразу после открытия WebSocket, не получают лишнее приветствие вместо
ответа на запрос. После обновления перезагрузите страницы порталов.

Запросы проверены на локальном стенде с одноразовыми сертификатами. Успешный
реальный вход на порталы с действующей ЭЦП пользователя ещё не подтверждён.

## Модули и сервисы

На главной странице есть раздел «Модули и сервисы»: выбор реализаций,
ограничения по сайтам, форматам, меткам времени и размеру партии. Настройки
действуют и на ожидающие подтверждения запросы. Ключи и пароли в них не сохраняются.

Доступны 8 реализаций отдельных функций: НУЦ Common Utils, НУЦ Basics,
Госзакупки NURSign, Самрук-Казына ИСЭЗ, СФД QIWI, 1С-Рейтинг ЭДО,
Uchet.kz и сведения о сертификате MetaDoc. Это не полный перенос плагинов.
В каталоге НУЦ 47 записей; остальные показаны с недоступным состоянием.
КНП, ЭСФ и Казначейство пока не реализованы. Java JAR не устанавливаются
и не исполняются в браузере, загружаемого кода в Tegin нет.
[Методы, ограничения и источники исследования](docs/modules.md).

## Данные и безопасность

- Закрытый ключ расшифровывается в отдельном Worker расширения. Ключ и пароль
  не передаются странице или фоновому обработчику.
- Worker завершается после операции, отмены, ошибки, смены файла или таймаута.
  Расширение не сохраняет контейнер, пароль или расшифрованный ключ.
- Внешняя сеть — только закреплённые службы НУЦ (полный список и состав запросов —
  в [privacy-policy.md](docs/privacy-policy.md)). Метка времени: `http://tsp.pki.gov.kz/`, когда
  пользователь подтверждает подпись с меткой; передаётся хеш подписи, политика и случайный
  nonce, не документ, ключ или пароль. Проверяются подпись TSA, цепочка НУЦ, EKU, хеш, nonce,
  политика и время. Перенаправления запрещены, адреса из сертификатов не запрашиваются.
  Телеметрии и серверной части нет.
- Сайт получает только подтверждённый результат: подпись либо публичный
  сертификат. Сам сайт определяет последующую отправку документа/подписи.
- Запрос сайта вместе с данными документа находится во временной `storage.session` до
  завершения операции. Ключи и пароли туда не попадают. Очистка выполняется при отмене,
  закрытии страницы и по трёхминутному таймауту.
- Постоянно (`storage.local`) хранятся только настройки модулей и зашифрованные паролем
  пользователя ключи заявок НУЦ до их удаления в разделе «Ключи заявок».
- Проверяются срок сертификата, соответствие ключевой пары и цепочка
  доверия. Встроенные открытые сертификаты НУЦ имеют зафиксированные SHA-256
  и источники в `extension/crypto/trust-store.js`.
- Для сертификатов НУЦ после открытия ключа проверяется отзыв: в НУЦ
  (`ocsp.pki.gov.kz`, при сбое — CRL с `crl.pki.gov.kz`, `crl1.pki.gov.kz`, `crl.root.gov.kz`)
  уходят серийный номер и хеши данных УЦ, служба видит IP-адрес. Ключ, пароль и документ не
  передаются. Без подтверждённого статуса «не отозван» операция не выполняется.
  Проверка файла подписи идёт без сети, онлайн-проверка отзыва — только по отметке
  пользователя.
- Само подписание не шифрует документ. Гарантировать стирание всех внутренних
  копий памяти браузера нельзя. Независимый аудит продукта ещё не проводился; пакет для
  аудитора — [docs/audit-package.md](docs/audit-package.md).

Лицензии библиотек и известный advisory с описанием применимости:
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Разработка и проверки

Нужны Node.js 22+, OpenSSL и Chromium для E2E. Это инструменты разработчика.

```sh
npm ci
npm test
npm run build
npm run test:e2e
npm run package
```

Для E2E при необходимости указать путь к тестовому Chromium через
`CHROMIUM_EXECUTABLE`. Используются отдельный временный профиль, локальный
тестовый сайт и одноразовые тестовые ключи; они удаляются после проверки.

Проверки с реальным сервисом меток времени запускаются явно:

```sh
node tests/tsp-live.mjs
NCA_LIVE_TSP=1 npm run test:e2e
```

Они отправляют только хеш одноразовой публичной тестовой подписи.

Дополнительная независимая проверка ГОСТ (Python, пакет gostcrypto 1.2.5):

```sh
node tests/gost-crosscheck.mjs | python3 tests/independent_gost.py
```

Используется Apache-2.0 реализация WebCrypto GOST с локальными исправлениями;
криптография не загружается с CDN. Сборка включает зависимости и лицензии.
Не добавляйте личные ключи или пароли в исходники и тесты.

Результаты независимых проверок: [docs/verification.md](docs/verification.md).

Подробности архитектуры: [docs/architecture.md](docs/architecture.md).
