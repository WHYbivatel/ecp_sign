# Пакет для внешнего аудитора

Срез на 13.11.2026, ветка `codex/nca-key-issuance`, кандидат 0.6.0 (код `530a4ae`, архивы — `store-submission.md`). Это материалы для подготовки
независимой проверки. Всё описанное ниже — внутренние проверки исполнителя по коду и тестам.
Независимым аудитом они не являются. Личные ключи, реальные аккаунты и документы не использовались.

## Что проверять

Расширение MV3 для Chromium и Firefox. Оно заменяет локальный сервис NCALayer
(`wss://127.0.0.1:13579`) для сайтов из `https://*.kz/*`. Ключ — файл PKCS#12 пользователя
или ключ, созданный расширением по заявке НУЦ. Своего сервера, нативного компонента и
удалённого кода нет.

| Компонент | Файл | Контекст | Доверие |
|---|---|---|---|
| Эмуляция сокета NCALayer | `extension/content/inject.js` | MAIN world страницы | недоверенный: страница может его переопределить |
| Мост | `extension/content/bridge.js` | isolated world | пересылает запрос с токеном документа |
| Фоновая очередь | `extension/background/background.js` | service worker | origin из `sender.url`, ожидающие запросы в `storage.session`, срок 180 с |
| Окно подтверждения | `extension/signing/approve.*` | страница расширения | показывает origin, файл, сертификат, проверку отзыва |
| Окно выпуска | `extension/signing/issue.*` | страница расширения | только `did.pki.gov.kz`, `nca.pki.gov.kz`, верхний фрейм |
| Криптография | `extension/crypto/worker.js` и модули `crypto/` | Worker | пароль и ключ попадают только сюда |
| Проверка отзыва | `crypto/ocsp.js`, `crl.js`, `revocation*.js` | Worker | закреплённые адреса НУЦ, ответы проверяются полностью |

Подробнее: [architecture.md](architecture.md) («Границы доверия»),
[certificate-revocation.md](certificate-revocation.md), [nca-key-issuance.md](nca-key-issuance.md),
[ncalayer-reference.md](ncalayer-reference.md).

## Активы

- Закрытый ключ пользователя и пароль контейнера.
- Документы и данные, которые сайт передаёт на подпись.
- Ключ заявки НУЦ до установки сертификата: зашифрован, лежит в `storage.local` и в файле резервной копии.
- Решение «подписать» и связь подписи с конкретным сайтом и запросом.
- Сведения о пользователе в сертификате (ФИО, ИИН, БИН).

## Входы

| Вход | Обработка | Ограничения |
|---|---|---|
| JSON по сокету | `signing/protocol.js`, `issuance-protocol.js`, адаптеры `modules/` | 3 МБ, белые списки, явный отказ на неизвестное |
| Файл ключа | `crypto/signer.js` (`openContainer`) в Worker | до 4 МБ, проверка MAC, итерации ограничены |
| CMS и цепочка от сайта | `crypto/cms-verify.js`, `chain.js` | форма RFC 5652 §5.3, подпись, срок, цепочка |
| XML | `crypto/xml.js` (`@xmldom/xmldom`, `xml-crypto`) | DTD отклоняется, подписывается весь документ |
| PDF (только локальный файл) | `crypto/pades.js` (разбор `pdf-lib`, своё инкрементальное обновление) | до 2 МБ, глубина 32, до 64 разделов ссылок; каждая используемая запись ссылок должна указывать на заголовок своего объекта; DocMDP (`PDF_CERTIFIED`), XFA, пустое поле подписи отклоняются; прежняя подпись, запрещающая любые изменения (`/P 1` в `/Lock` поля или в FieldMDP), — отказ `PDF_LOCKED`; результат проверяется после подписи: исходные байты — префикс, прежние ByteRange не выходят за исходный файл, новая CMS проверяется |
| Ответы OCSP, CRL, TSA | `crypto/ocsp.js`, `crl.js`, `timestamp.js` | только закреплённые URL, тип, размер, таймаут, без перенаправлений |
| Резервная копия ключа заявки | `signing/issue.js` | до 64 КБ, проверка структуры; не заменяет сохранённую запись |
| Локальный файл в окне подписи | `signing/approve.js` → Worker | документ внутри подписи, XML, PDF — до 2 МБ; отдельная подпись CMS/CAdES-BES и исходный файл при её проверке — до 16 МБ; файл подписи — до 8 МБ (`docs/file-limits.md`) |

Сеть: `connect-src` в CSP страниц расширения содержит только `tsp`, `ocsp`, `crl`, `crl1.pki.gov.kz`
и `crl.root.gov.kz`. В НУЦ уходят серийные номера сертификатов и хеш документа для метки
времени. Адреса из AIA и CRL DP проверяемого сертификата не используются.

## Сборка и воспроизведение

```bash
npm ci
npm run build              # dist/chromium, dist/firefox
npm test                   # unit, 185 тестов
npm run test:e2e           # браузерные E2E (Chromium), включая лимиты файлов
node tests/e2e-update.mjs  # обновление с опубликованной сборки, откат, перенос через резервные копии
npm run test:e2e:firefox   # выпуск и проверка отзыва в Firefox
node tests/e2e-revocation.mjs
npm run test:revocation-live   # живые службы НУЦ, только публичные материалы
node tests/fuzz-pdf.mjs 3000   # детерминированный фаззинг PDF
DSS_VALIDATOR=<каталог> node tests/cades-lt-crosscheck.mjs   # CAdES-LT/LTA в EU DSS, синтетическая PKI
DSS_VALIDATOR=<каталог> node tests/cades-lt-live.mjs         # то же с метками и OCSP/CRL НУЦ
NCA_KALKAN_JARS=$(node scripts/fetch-kalkan.mjs .kalkan) node tests/kalkan-crosscheck.mjs
```

- Две сборки подряд дают побайтно одинаковый `dist/`. Архивы `.zip` от `scripts/package.mjs` тоже
  воспроизводимы: имена по порядку, фиксированные время и режим; `verify-package.mjs` упаковывает повторно
  и сравнивает байты (в пределах одной линии Node, в CI — 22). Исходники для AMO —
  `dist/tegin-source-<версия>.zip` (`git archive` коммита), без ключей, `.env`, `dist/` и `node_modules/`.
- Тестовые сборки включаются только переменными `TEGIN_TEST_ISSUANCE_ANCHORS` и
  `TEGIN_TEST_REVOCATION_ISSUERS`. Каталог задаётся `TEGIN_DIST` вне `dist/`, в имени
  расширения есть пометка. В обычном `dist/` тестовых хуков, синтетических имён и паролей нет
  (проверено поиском 12.11.2026).
- Kalkan 0.7.8 берётся из официального `ncalayer.zip` с закреплёнными SHA-256
  (`scripts/fetch-kalkan.mjs`).
- CI: `.github/workflows/ci.yml`. Последний полный прогон — [43274778014](https://github.com/WHYbivatel/ecp_sign/actions/runs/43274778014) (`1bc8bbb`):
  unit на Windows, macOS и Ubuntu, E2E Chrome, Edge, Chromium и Firefox (включая проверку отзыва), Kalkan
  (XML, PKCS#12, CSR), EU DSS и pyHanko (PAdES, CAdES-LT/LTA, PDF из браузера), упаковка с проверкой воспроизводимости.

## Сценарии для внешней проверки

1. **`vendor/gost`.** Сравнить с исходником, указанным в `THIRD_PARTY_NOTICES.md`, построчно: проверки `r` и `s`,
   `invMod`, приведение по модулю, разбор точек. Прогнать подпись и проверку ГОСТ-256 и ГОСТ-512 на
   10⁵ случайных ключах и сообщениях против Kalkan (`tests/kalkan-crosscheck.mjs` даёт обвязку). Проверить
   функции, которые вызываются редко (ветви отрицательных чисел, переносов): дефект `invMod` прятался именно там.
   Отдельно: отсутствие constant-time и что это значит для ключа в браузере.
2. **Цепочка от сайта.** `signerParams.chain` (`scope: 'site'`): сайт передаёт сертификаты, которым доверяется
   подписанная им операция. Сценарии: сайт подставляет свой корень и самоподписанный сертификат пользователя;
   промежуточный УЦ без `basicConstraints` или с `pathLen`, нарушенным цепочкой; цепочка с SHA-1; корень НУЦ
   плюс чужой промежуточный. Ожидание: окно не показывает «Цепочка НУЦ подтверждена» ни в одном из них, а
   поведение совпадает с NCALayer там, где это задокументировано (`ncalayer-reference.md`).
3. **Сложные входы.** PDF: гибридные ссылки, потоки объектов, BOM и мусор до `%PDF-`, несколько ревизий
   с подписями, большие сканы до 2 МБ (фаззер `tests/fuzz-pdf.mjs` как основа). XML: пространства имён по
   умолчанию, `xml:base`, сущности (DTD отклоняется — подтвердить), XPath на узел с ID-атрибутом без схемы,
   несколько подписей. CMS: BER неопределённой длины, отдельная подпись с подставленным исходником,
   `digestAlgorithms`, не совпадающий с алгоритмом подписанта, лишние подписанты, файл подписи у лимита 8 МБ.
   ASN.1 forge: фаззинг с покрытием.
4. **Обновление и перенос.** Повторить `tests/e2e-update.mjs` и `tests/e2e-update-firefox.mjs`; отдельно
   оценить импорт резервной копии от третьего лица (раздел ниже).

## Открытые замечания и вопросы

Новое на 12.11.2026:

- **Срок хранения ключа заявки — закрыто в `f098778` (решение владельца: список).** Раздел
  «Ключи заявок» показывает локальные записи и удаляет выбранную целиком после подтверждения.
  Окно установки после сохранения `.p12` предлагает удалить ключ. CN больше не хранится и
  удаляется из старых записей. Автоудаления нет: запись живёт до удаления пользователем.
  Проверено E2E Chromium: удаление после закрытия окна, сохранность другой записи,
  восстановление из резервной копии.
- **PAdES пересохраняет документ — закрыто (этап 6).** Подпись добавляется инкрементальным
  обновлением своим кодом, `pdf-lib` только разбирает файл; `@signpdf` и полифилл `buffer` удалены.
  Исходные байты остаются префиксом результата. Повреждённый файл больше не подписывается в
  восстановленном виде: цепочка перекрёстных ссылок проверяется до открытия ключа. Фаззинг
  `tests/fuzz-pdf.mjs` 3000: принято 61, все 61 читаются строгим парсером pyHanko, все подписи
  `ENTIRE_FILE`; из отклонённых 91 pyHanko читает (90 — строгий разбор объектов `pdf-lib`, как
  раньше; 1 — запись ссылок не на свой объект). Предпросмотра по-прежнему нет.
- **CAdES-LT/LTA (этап 6) — что смотреть.** Новый `extension/crypto/cades-lt.js` собирает
  SignedData из исходных TLV: подписанные поля, сертификаты, CRL и OCSP не перекодируются,
  перекодируются только контейнеры. Наборы `certificates` и `crls` не сортируются (RFC 5652
  допускает BER вне подписанных атрибутов; DSS принимает). Доказательства отзыва передаются
  неперечислимым полем `evidence` результата `checkPath`, чтобы не попадать в сообщения и журнал.
  Проверка архивной метки строже DSS: любой хеш индекса должен найтись среди текущих элементов
  подписи. Формат доступен только из локального окна; `protocol.js` пропускает только перечисленные
  поля запроса сайта, поэтому сайт не может включить его сам. Ключ ГОСТ и цепочка не НУЦ отклоняются
  до любых запросов в сеть (E2E).
- **Импорт резервной копии.** Файл резервной копии может прийти от третьего лица. Ключ из
  него используется, только если НУЦ выпустил сертификат на его открытый ключ и пользователь
  знает пароль. Сценарий подброшенного ключа стоит оценить.
- **Диагностический журнал.** Хранит имена полей запроса, но не значения. Это `storage.session`:
  он не сохраняется между сеансами и очищается при закрытии вкладки. Имя поля проходит
  фильтр `[A-Za-z0-9_.-]{1,64}`, поэтому теоретически может совпасть с ИИН, если сайт
  использует ИИН как ключ объекта.

Из этапа 3, без изменений:

- Big-integer ГОСТ из `vendor/gost` и RSA в forge не constant-time; побочные каналы в браузере не оценивались.
- Строку пароля и её копии в куче JS стереть нельзя. Буфер контейнера обнуляется.
- В окне подтверждения показан origin фрейма, а не страницы верхнего уровня.
- В обычной сборке разрешены `http://localhost` и `127.0.0.1`.
- При проверке цепочек и CMS принимаются подписи RSA с SHA-1. digestAlgorithms в CMS не сверяется
  с алгоритмом подписанта (как в OpenSSL).
- Доверие к корням из `signerParams.chain` сайта (`scope: 'site'`) стоит сверить с семантикой NCALayer.
- Разбор ASN.1 в forge проверен только коротким фаззингом, без покрытия.

Не проверялось: реальные порталы с личным ключом, подписанная сборка из AMO и Chrome Web
Store, Windows ARM64 и Linux ARM64, аппаратные носители.
