# Ограничения размера файлов

Обновлено 13 ноября 2026 года для кандидата 0.6.0.

## Действующие лимиты

| Где | Операция | Лимит | Почему |
|---|---|---|---|
| Окно подписи, локальный файл | CMS/CAdES с документом внутри, CAdES-T/LT/LTA, XML, PAdES | 2 МБ | документ целиком идёт в base64-запрос и в структуру подписи; память растёт примерно на 30 байт на байт входа |
| Окно подписи, локальный файл | CMS и CAdES-BES, отдельная подпись (`cms-detached`, `cades-detached`) | **16 МБ** | подписывается хеш, рост памяти почти не зависит от размера |
| Окно проверки | файл подписи | 8 МБ | лимит ядра `verifyCms` |
| Окно проверки | исходный документ для отдельной подписи | **16 МБ** | только хешируется |
| Запрос сайта (API NCALayer) | документ | 2 МБ | без изменений |
| Контейнер `.p12`/`.pfx` | | 4 МБ | без изменений |

Файл больше 2 МБ в формате «документ внутри подписи» отклоняется с подсказкой выбрать отдельную подпись, и раскрываются
дополнительные настройки. После смены формата тот же файл принимается без повторного выбора.

## В браузере

`node tests/e2e-limits.mjs`, Chromium (Playwright), Linux x64, 13 ноября 2026 года. Память считается как прирост RSS
процесса расширения относительно начала операции. В него входят копия файла на странице, base64 для предпросмотра и
буфер в Worker.

| Операция, 16 МБ | Время | Прирост RSS рендерера |
|---|---|---|
| ГОСТ 512, отдельная CMS | 7,2 с | +292 МБ |
| RSA 2048, отдельная CMS | 4,0 с | +236 МБ |
| проверка отдельной подписи с исходным файлом 16 МБ | 1,0 с | в пределах уже занятой памяти |

Тест проверяет:

- 2 МБ с документом внутри принимается, а 2 МБ + 1 байт отклоняется с подсказкой и раскрытыми настройками;
- повтор после отказа: тот же файл на 16 МБ принимается после выбора отдельной подписи;
- 16 МБ + 1 байт отклоняется и для отдельной подписи;
- отмена: во время подписи ГОСТ пользователь переключается на «Проверить». Worker останавливается, результат и
  скачивание не появляются, пароль стирается. Повторная подпись того же файла проходит;
- подпись RSA на 16 МБ проверяется OpenSSL (`cms -verify -content`) по исходному файлу;
- проверка в окне: исходный файл 16 МБ + 1 байт отклоняется, после выбора правильного файла подпись верна;
- файл подписи больше 8 МБ отклоняется.

Тест входит в `npm run test:e2e` (Linux, Chromium) и в задачу CI `full-e2e-browsers` (Chrome и Edge на Windows,
Chrome на macOS).

## Решение

Лимит поднят только для отдельной подписи CMS/CAdES-BES и для исходного файла при её проверке. Для форматов
с документом внутри при 16 МБ память доходит до 0,6 ГБ уже в ядре, а в браузере добавляются копии на странице.
Для PAdES ограничение задаёт разбор PDF: текстовый PDF на 16 МБ занимает 6,5 с и 475 МБ. Эти лимиты остаются 2 МБ.
CAdES-T/LT/LTA в окне подписи создаются только с документом внутри, поэтому тоже остаются в пределах 2 МБ.
