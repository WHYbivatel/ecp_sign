# Архитектура 0.3

## Принцип работы

Страница → адаптер WebSocket в MAIN world → изолированный content script →
фоновый обработчик → доверенное окно подтверждения → отдельный Worker
криптографии → результат → исходный frame страницы.

Дополнительные программы и реальные соединения с localhost:13579 не нужны.
Перехватываются только WebSocket/fetch обращения к localhost, 127.0.0.1 или
[::1] на порту 13579. Остальные соединения страницы остаются обычными.
HTTP-пробы через изображения/iframe и произвольные модули NCALayer не эмулируются.

## Границы доверия

Страница и её скрипты недоверенные. Адрес операции берётся из sender.url,
а tab/frame — из метаданных браузера. Связь с конкретным документом страницы
проверяется через случайный идентификатор изолированного content script.
После навигации такой идентификатор больше не подтверждается.

Окно подтверждения получает запрос по случайному ID. Читать или завершать
его могут только сообщения от страницы approve.html самого расширения.
На сайт возвращается результат только его запроса. Разрешение доступа к
сайту само по себе не разрешает использование ключа: требуется подтверждение.

Ключ и пароль направляются из окна расширения непосредственно в Worker.
Фоновый обработчик и скрипты сайта их не получают. В storage.session хранятся
только документы и служебные сведения незавершённых запросов. Запросы
удаляются по завершении, отмене, закрытии страницы и по alarm-таймауту.
Очередь мутаций и ограничения количества запросов уменьшают возможность
создать множество окон из разных frames.

## Криптография

- PKCS#12, PBES2/AES и PKCS#12 PBE/3DES/RC2: node-forge.
- RSA/SHA-256: native Web Crypto. RSA-верификация forge не используется.
- ГОСТ: Apache-2.0 WebCrypto GOST, включённый в пакет, см. notices.
- CMS SignedData: RFC 5652, issuer/serial идентифицирует сертификат.
  CAdES-BES использует подписанные contentType/messageDigest и
  SigningCertificateV2 с SHA-256 отпечатком сертификата по RFC 5035.
- XMLDSig: enveloped transform, exclusive canonicalization, полный документ.
  XML с DTD, вложенными внешними сущностями и существующей подписью отклоняется.
- Для ГОСТ закрытый скаляр проверяется вычислением открытого ключа.
  Производится самопроверка каждой сформированной подписи.
- Срок сертификата и назначение KeyUsage проверяются локально. EKU/ИИН/БИН/
  серийный номер из signerParams проверяются до выдачи подписи.

Цепочка сертификата строится локально до встроенных корней НУЦ или явно
указанных сайтом PEM-якорей. Проверяются подписи, сроки, CA, KeyUsage,
pathLenConstraint, AKI/SKI, циклы, неизвестные критические расширения и
принадлежность корня к хранилищу по SHA-256. Публичные ГОСТ-точки проверяются
на принадлежность кривой и подгруппе. Статус отзыва не устанавливается.
Открытие контейнера не означает полную проверку действительности сертификата.

RFC3161 использует фиксированный сервис НУЦ и профиль политики
1.2.398.3.3.2.6.4. После согласия пользователя наружу отправляется только
ГОСТ-512 хеш байтов подписи, nonce и профиль. Закрытый ключ, пароль и документ
остаются в браузере. Ответ проверяется до включения токена в CAdES-T:
CMS-подпись, ESS-связь с сертификатом, цепочка НУЦ, критический EKU timestamp,
messageImprint, policy, nonce и время. Ошибка TSA завершает операцию ошибкой.
Внешний URL не принимается от сайта. CSP разрешает сеть только этому хосту.

Режим проверки CMS не открывает PKCS#12. Проверяются все подписанты,
contentType/messageDigest, уникальность подписанных атрибутов, ESS-привязка,
соответствие вложенного/отдельного документа и криптография. Метки времени
проверяются без сети на дату выпуска; отзыв по-прежнему не проверяется.

## Подтверждённые проверки

- Node crypto и OpenSSL: RSA и CMS, attached/detached.
- XML-crypto: RSA XMLDSig, подмена документа отклоняется.
- KalkanCrypt 0.7.8 / XMLDSig 0.5.1: RSA, ГОСТ-512/256/2004 CMS/CAdES-BES attached/detached и подпись хеша;
  RSA, ГОСТ-512/2004 XMLDSig; CAdES-T с настоящим токеном НУЦ.
- Python gostcrypto: Streebog-512 и ГОСТ-512, подмена хеша отклоняется.
- Открытие общедоступного тестового контейнера НУЦ ГОСТ-512 (истёкшего;
  исключительно в проверке движка с тестовой датой, вне runtime расширения).
- Chromium: настоящий MV3 worker, запрос от страницы, неверный пароль,
  явное подтверждение, CMS, XML, ГОСТ, отмена/навигация, локальная проверка,
  CAdES-T и сеть только для хеша в TSA; отсутствие сохранённых ключей. Реальные пользовательские ключи не использовались.

Отдельные результаты проверки через официальный Kalkan, если доступны,
записываются в docs/verification.md. Наличие транспорта NCALayer не доказывает
работу полного сценария конкретного портала.

## Что остаётся до полной совместимости

Проверки реальных сценариев выбранных порталов, дополнительные реальные контейнеры, OCSP/CRL, PAdES и CAdES-LT/LTA,
возможные новые модули и параметры API, аудит и публикация в магазинах.
Firefox имеет отдельный manifest, но не проходил сквозную проверку.
Safari требует отдельной реализации/упаковки.
