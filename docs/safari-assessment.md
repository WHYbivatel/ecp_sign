# Safari: оценка переноса

Статус: **не реализовано, не проверено**. Safari на сервере разработки (Linux) не запускается.
Ниже — что требуется и где ожидаются риски. Пункты с пометкой «проверить» не подтверждены
ни документацией, ни прогоном и до прогона на macOS считаются неизвестными.

## Упаковка и распространение

- Safari Web Extension поставляется внутри приложения macOS (и отдельно iOS/iPadOS).
  Проект Xcode создаётся из `dist/chromium` конвертером `xcrun safari-web-extension-converter`.
- Нужны Apple Developer Program, подпись и нотаризация. Распространение — Mac App Store
  или подписанное приложение вне магазина (проверить текущие правила Apple для расширений
  вне App Store).
- Отдельная сборка: `background.service_worker` или `background.scripts` (проверить, что
  выбирает конвертер), без `minimum_chrome_version`. Удалённого кода нет, поэтому требование
  App Review к исполняемому коду выполняется без изменений.
- Обновления идут через обновление приложения, а не через ZIP с сайта. Путь «обновить
  распакованную папку на месте» к Safari не применим.

## API, которые использует расширение

| API | Где | Риск в Safari |
|---|---|---|
| Content script `world: 'MAIN'` в манифесте и в `scripting.registerContentScripts` | Подмена `WebSocket` для протокола NCALayer (`content/inject.js`) | **Главный риск.** Без MAIN world страница портала не видит адаптер. Проверить поддержку; запасной вариант — вставка `<script src>` из web-accessible ресурса, что меняет модель доверия и требует отдельного разбора |
| `windows.create` (окно подтверждения), `windows.onRemoved`, `windows.update/remove` | Окна подписи и выпуска | macOS — проверить тип окна `popup`. iOS/iPadOS: отдельных окон нет, нужен другой интерфейс подтверждения |
| `storage.session` | Ожидающие запросы, диагностика | Проверить наличие; без него ожидающие запросы пришлось бы хранить иначе, что меняет гарантию «не переживает перезапуск» |
| `storage.local` | Зашифрованный ключ заявки, настройки | Проверить квоту и очистку данных расширения при удалении приложения |
| `alarms` | Срок жизни запроса 180 с | Проверить минимальный интервал и срабатывание при остановленном фоне |
| `permissions.request` для `https://*/*` | Ручное подключение сайта | Safari сам управляет доступом к сайтам: у пользователя свои настройки доступа к сайтам, поведение кнопки «Подключить сайт» нужно проверить |
| `action.setBadge*`, `action.onClicked` | Значок | Низкий |
| `tabs.query/get/create/update/reload/sendMessage`, `tabs.onRemoved` | Привязка ответа к вкладке и фрейму | Проверить `frameId` в `sender` и `tabs.sendMessage(..., {frameId})`: на этом держится привязка ответа к iframe |
| Web Worker в странице расширения, Web Crypto (AES-GCM, PBKDF2, SHA) | Расшифровка ключа и PKCS#12 | Низкий; ГОСТ реализован на JS |
| `<a download>` с `blob:` из страницы расширения | Сохранение `.p12` и резервной копии ключа заявки | Проверить: без скачивания выпуск ключа не может завершиться, потому что портал узнаёт об установке только после сохранения файла |
| `<input type=file>` в окне расширения | Выбор `.p12` | Низкий на macOS |

## Порядок работ, если Safari понадобится

1. На macOS с Xcode сконвертировать `dist/chromium` и прогнать в Safari Technology Preview
   ручной сценарий из `docs/verification.md`: адаптер на странице, подпись CMS, выпуск ключа
   на копии страниц НУЦ.
2. По результату решить судьбу MAIN world и скачивания файлов — это единственные пункты,
   из-за которых может понадобиться менять архитектуру.
3. Автоматизация: способа установить и включить расширение через `safaridriver` не найдено
   (проверить). Если его нет, E2E в CI по образцу Chrome и Firefox не получится, и понадобится
   ручной прогон или XCUITest.
4. Только после этого — упаковка, подпись, App Store.

Safari не входит в заявленную поддержку и в матрицу «подтверждено» не попадает.
