# Матрица поддержки Tegin

Срез на 13.11.2026, ветка `codex/nca-key-issuance`, кандидат 0.6.0 (код `5b3eae2`). Одна таблица на сценарий и отдельная таблица
на браузер и ОС. Полная замена NCALayer заявляется только для строк, где заполнен последний столбец.

Статусы независимы друг от друга:

- **Реализовано** — код есть в расширении.
- **Проверено локально** — unit-, контрактные или браузерные тесты на синтетических ключах и
  обезличенных копиях страниц.
- **Независимый валидатор** — результат принят не кодом Tegin: Kalkan 0.7.8 (из официального
  `ncalayer.zip`, SHA-256 JAR закреплены), Kalkan XMLDSig 0.4 и официальный `XMLUtil` 0.8.8 из того же
  архива, а также XMLDSig 0.5.2 и `XMLUtil` 0.9.2 — версии, до которых установленный NCALayer обновляется по
  подписанному каталогу НУЦ (хеши из каталога); EU DSS 6.5.1 и pyHanko 0.38.0 для PAdES и CAdES-LT/LTA;
  OpenSSL 3, xml-crypto. Это внутренние проверки на синтетических данных, не независимый аудит.
- **Подтверждено на портале** — владелец своим ключом завершил операцию на настоящем портале.

## Что требуется для следующего статуса

- **Портал, установка:** владелец выполняет `nca-install-owner-guide.md` для уже выпущенной заявки.
- **Аппаратные носители:** SafeNet eToken 5110 с SafeNet Authentication Client на Windows 11 x64 или Ubuntu 22.04 x64
  (или JaCarta с PKCS#11 производителя); прототип компонента готов, план испытаний — в `hardware-tokens.md`.
- **ЭДО, Госзакупки, Самрук-Казына:** развёрнутый контракт или запросы страницы, полученные владельцем. Для
  NURSign `type: "xml"` — обезличенный запрос настоящей страницы и прогон владельца: примет ли сервер подпись.
- **Магазины:** решения владельца из `store-submission.md` (рекомендации подготовлены), аккаунты разработчика,
  контакт на `privacy.html` (страница готова, выходит с 0.6.0); подача — отдельное действие.
