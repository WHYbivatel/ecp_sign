# Совместимость Tegin с порталами и API NCALayer

Срез от 9 ноября 2026 года, этап 1 плана улучшения. Ветка `codex/portal-compatibility`.

## Статусы

- **Реализовано** — обработчик есть в расширении.
- **Проверено локально** — запрос с точной формой портала прошёл контрактные тесты (`tests/portal-contracts.test.js`) и/или браузерный сценарий (`tests/e2e.mjs`) на одноразовых синтетических ключах. Адреса порталов в E2E обслуживает локальный маршрут Playwright. Это **не** вход на портал.
- **Подтверждено на портале** — владелец сертификата НУЦ завершил операцию на настоящем портале. На момент среза **ни один сценарий не подтверждён**: личные ключи и учётные записи не использовались.

## Найденные расхождения

Сверены с кодом официальных модулей НУЦ (Basics 0.4.10, Common Utils 0.3.4); эталон и полная
таблица — [ncalayer-reference.md](ncalayer-reference.md).

1. **`keyType` в Common Utils** — исправлено: ключи фильтруются по правилу NCALayer (тип по
   KeyUsage, EKU и алгоритму подписи сертификата). Сторонние модули (ИСЭЗ, 1С-Рейтинг, Uchet)
   сохраняют своё правило через EKU.
2. **`details` в ошибке Basics** — совпадает: NCALayer передаёт `details` только при наличии
   причины исключения.
3. **Форма `getKeyInfo`** — исправлено: эталонные поля и форматы Kalkan, сверены на
   синтетических сертификатах официальными классами. `alias` не передаётся.
4. **Таймаут** — у NCALayer его нет. Tegin через 3 минуты отвечает отменой
   (`{status:true, body:{}}`), это ближайший эквивалент; оставлено.
5. **Резервный таймер `bridge.js`** — исправлено: отвечает формой своего модуля.
6. **Просроченный запрос, завершённый новым** — исправлено: окно закрывается.
7. **Common Utils** — ошибки `500`, отмена `action.canceled`, `uuid` возвращается,
   `changeLocale` → `{"code":"200"}`. raw и массив данных для любого формата — официальное
   поведение Basics, а не расширение Tegin. `getActiveTokens` возвращает `[]`: токены не
   поддерживаются.
8. **ncalayer-js-client сам обращается к HTTP API KAZTOKEN** (`https://127.0.0.1:24680/`).
   Tegin этот адрес не перехватывает. Если KAZTOKEN desktop установлен, CMS-подпись такого
   сайта пойдёт в KAZTOKEN, а не в Tegin.
9. **Открыто, решение владельца:** Basics возвращает CMS в PEM (`-----BEGIN CMS-----`), а одну
   raw-подпись — строкой; Tegin отдаёт base64 и всегда массив. Смена затронет сайты, уже
   настроенные на Tegin (в том числе ЭДО).

## Что не подтверждено

- Вход и подписание на настоящих eGov, кабинете НУЦ и Tegin ЭДО.
- Контракт Tegin ЭДО описан по сведениям владельца о коммите `2961da5`. Исполнитель код не читал. Соответствие текущей развёрнутой версии ЭДО этому коммиту не установлено.
- Принятие профилей ЭДО нормализатором не доказывает ни полного подписания настоящим ключом НУЦ, ни принятия подписи сервером ЭДО.
- Метка времени от настоящей службы `tsp.pki.gov.kz` для профиля документа ЭДО не запрашивалась: live-проверка (`NCA_LIVE_TSP=1`) не запускалась.
- Реальный XML заявлений eGov: доступен только после входа.
- Причина исходной ошибки открытия контейнера пользователя (этап 0) по-прежнему не подтверждена. Этап 1 её не касался.

## Ручная проверка владельцем сертификата

Пароль, контейнер, подписанные документы и снимки с ФИО/ИИН в чат не передавать. Подписанный XML содержит сертификат, то есть персональные данные.

Подготовка:

1. Собрать ветку (`npm ci && npm run build`) и загрузить `dist/chromium` как распакованное расширение в отдельном профиле Chrome.
2. NCALayer можно не запускать: Tegin перехватывает `wss://127.0.0.1:13579` на страницах `*.kz`.

| Сценарий | Действия | Ожидаемый результат |
| --- | --- | --- |
| eGov, вход | `https://idp.egov.kz/idp/login` → вход по ЭЦП. В окне Tegin выбрать свой `.p12`, ввести пароль, проверить строку «Подходит для входа», нажать «Подтвердить вход» | Заголовок «Вход на сайт», адрес `https://egov.kz`. После подтверждения eGov открывает личный кабинет |
| eGov, отмена | То же, но нажать «Отмена» | eGov остаётся на странице входа без сообщений об ошибке Tegin |
| Кабинет НУЦ, вход | `https://nca.pki.gov.kz/ua/login.xhtml` → вход по ЭЦП → ключ НУЦ → «Подтвердить» | Заголовок «Подтверждение на сайте НУЦ», статус «Цепочка НУЦ подтверждена», затем вход в кабинет |
| Tegin ЭДО | Вход и подписание тестового документа в ЭДО ключом НУЦ | Окно Tegin показывает адрес ЭДО; для документа видна заметка «Метка времени НУЦ». Ключ вне цепочки НУЦ отклоняется ещё до подтверждения. После подтверждения ЭДО принимает подпись. Если ЭДО отвечает ошибкой формата, сравнить развёрнутую версию с коммитом `2961da5` |

Безопасная диагностика при ошибке, которую можно прислать:

- текст ошибки в окне Tegin и на странице портала;
- версии браузера и Tegin;
- JSON из блока «Диагностика ошибки» (кнопка «Скопировать»; блок появляется при ошибке ключа или сертификата). Он не содержит имени файла, пароля, ФИО, ИИН и сертификата.

Не присылать: HAR-файлы и экспорт сети (в них cookies сеанса), подписанные файлы, снимки окна с данными сертификата, сам контейнер.
