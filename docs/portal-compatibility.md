# Совместимость Tegin с порталами и API NCALayer

Срез от 9 ноября 2026 года, этап 1 плана улучшения. Ветка `codex/portal-compatibility`.

## Статусы

- **Реализовано** — обработчик есть в расширении.
- **Проверено локально** — запрос с точной формой портала прошёл контрактные тесты (`tests/portal-contracts.test.js`) и/или браузерный сценарий (`tests/e2e.mjs`) на одноразовых синтетических ключах. Адреса порталов в E2E обслуживает локальный маршрут Playwright. Это **не** вход на портал.
- **Подтверждено на портале** — владелец сертификата НУЦ завершил операцию на настоящем портале. На момент среза **ни один сценарий не подтверждён**: личные ключи и учётные записи не использовались.

## Найденные расхождения

Ни одно из них не подтверждено как ломающее вход или подпись на eGov, в кабинете НУЦ или SDK НУЦ, поэтому поведение не менялось. Исправлять «на всякий случай» без подтверждённого контракта запрещено планом.

1. **`keyType` в Common Utils не сужает выбор сертификата.** По описанию ncalayer-js-client, NCALayer показывает только ключи нужного типа (SIGNATURE/AUTHENTICATION). Официального описания нет. Сторонние адаптеры Tegin (ИСЭЗ, 1С-Рейтинг, Uchet) переводят этот же аргумент в EKU, а базовый Common Utils — нет. Целевые порталы используют basics, поэтому на них это не влияет. Для сайтов на Common Utils пользователь может выбрать ключ другого назначения; сервер сайта при этом проверяет сертификат сам. Решение — ограничивать по EKU или нет — требует подтверждения поведения NCALayer. Каталог модулей теперь прямо об этом говорит.
2. **В ошибке basics нет поля `details`.** ncalayer-js-client формирует текст как `code: message (details)` и показывает `(undefined)`. В официальной wiki формат ошибки не описан, значение `details` в NCALayer неизвестно.
3. **Форма ответа `getKeyInfo`** не сверена с NCALayer: публичного описания нет.
4. **Таймаут сообщается как отмена** (`{status:true, body:{}}`), поэтому ncalayer-js-client показывает `canceledByUser`. Поведение NCALayer при долгом ожидании не документировано.
5. **Резервный таймер `bridge.js` (185 с)** отвечает в форме Common Utils и на basics-запрос. Он срабатывает, только если не сработал alarm фонового скрипта (180 с). eGov такой ответ игнорирует, клиенты SIGEX и НУЦ получают ошибку.
6. **Просроченный запрос, завершённый при поступлении нового** (`background.js`, проверка `expires` в `nca:request`), не закрывает своё окно. Подтвердить в этом окне уже нельзя: оно сообщит, что запрос недействителен. Обычный путь через alarm окно закрывает.
7. **Расширения Tegin сверх контракта НУЦ:** формат `raw`; массив данных для CMS (wiki НУЦ описывает массив только для XML, ncalayer-js-client его отправляет); `changeLocale` всегда возвращает `true`; `getActiveTokens` всегда возвращает `[]`.
8. **ncalayer-js-client сам обращается к HTTP API KAZTOKEN** (`https://127.0.0.1:24680/`). Tegin этот адрес не перехватывает. Если KAZTOKEN desktop установлен, CMS-подпись такого сайта пойдёт в KAZTOKEN, а не в Tegin.

## Что не подтверждено

- Вход и подписание на настоящих eGov, кабинете НУЦ и Tegin ЭДО.
- Текущий контракт Tegin ЭДО: код интеграции недоступен.
- Реальный XML заявлений eGov: доступен только после входа.
- Причина исходной ошибки открытия контейнера пользователя (этап 0) по-прежнему не подтверждена. Этап 1 её не касался.

## Ручная проверка владельцем сертификата

Пароль, контейнер, подписанные документы и снимки с ФИО/ИИН в чат не передавать. Подписанный XML содержит сертификат, то есть персональные данные.

Подготовка:

1. Собрать ветку (`npm ci && npm run build`) и загрузить `dist/chromium` как распакованное расширение в отдельном профиле Chrome.
2. NCALayer можно не запускать: Tegin перехватывает `wss://127.0.0.1:13579` на страницах `*.kz`.

| Сценарий | Действия | Ожидаемый результат |
| --- | --- | --- |
| eGov, вход | `https://idp.egov.kz/idp/login` → вход по ЭЦП. В окне Tegin выбрать свой `.p12`, ввести пароль, проверить строку «Подходит для входа», нажать «Подтвердить вход» | Заголовок «Вход на сайт», адрес `https://egov.kz`. После подтверждения eGov открывает личный кабинет |
| eGov, отмена | То же, но нажать «Отмена» | eGov остаётся на странице входа без сообщений об ошибке Tegin |
| Кабинет НУЦ, вход | `https://nca.pki.gov.kz/ua/login.xhtml` → вход по ЭЦП → ключ НУЦ → «Подтвердить» | Заголовок «Подтверждение на сайте НУЦ», статус «Цепочка НУЦ подтверждена», затем вход в кабинет |
| Tegin ЭДО | Вход и подписание тестового документа в ЭДО | Окно Tegin показывает адрес ЭДО. После подтверждения ЭДО принимает подпись. Если ЭДО отвечает ошибкой формата, это расхождение контракта: нужен код интеграции |

Безопасная диагностика при ошибке, которую можно прислать:

- текст ошибки в окне Tegin и на странице портала;
- версии браузера и Tegin;
- JSON из блока «Диагностика ошибки» (кнопка «Скопировать»; блок появляется при ошибке ключа или сертификата). Он не содержит имени файла, пароля, ФИО, ИИН и сертификата.

Не присылать: HAR-файлы и экспорт сети (в них cookies сеанса), подписанные файлы, снимки окна с данными сертификата, сам контейнер.
